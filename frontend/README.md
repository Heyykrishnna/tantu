# tantu frontend

The Next.js/React foundation and connected-work application: secure sign-in, workspace switching, task/page lists and detail editing, invitations, files, activity and internal job controls. Data comes from the real Fastify service; there is no seeded production dashboard.

## Run

Use Node.js 24/npm 11 and the [local setup guide](../docs/l1a/setup.md). Start the database, backend and worker before using the application:

```bash
npm run dev
```

Open [localhost:3000](http://localhost:3000). `/api/v1` is rewritten to `BACKEND_ORIGIN`, defaulting to loopback port 4000. [.env.example](.env.example) contains the public-service routing setting; credentials remain on the backend. Build-time routing must match the actual deployment and the backend's exact `APP_ORIGIN`.

## Behavior and validation

Task/page IDs survive routes and reloads. Saves use operation keys and expected versions; conflicts retain the draft. Session storage holds user/workspace/record-scoped drafts and retry identity on the current device until saved or explicitly cleared by logout. The reference-inspired interface uses a charcoal dark theme by default and a pale slate/lavender light theme, compact navigation, layered panels, table rows, consistent SVG icons and a native mobile navigation drawer. Theme preference persists locally. Native controls, visible focus and a keyboard command dialog provide the local UI baseline.

Page editing supports bounded Tiptap/ProseMirror paragraphs, headings and bold/italic/strike/inline-code marks over the existing collaborative Yjs body through persisted updates, current-access polling and browser-session draft recovery. Projects, calendar, Mail and Collections use real scoped APIs. Script/HTML text is never rendered as active HTML. Read-only grants disable edits. Files remain quarantined until the actual scanner approves them; no active attachment preview is implemented.

Production builds use Next’s webpack builder with the matching Tailwind PostCSS adapter. Development retains the existing Turbopack setup. Run `npm run lint`, `npm run typecheck` and `npm run build`. From the root, `npm run check:l1b` also tests the built interface through actual HTTP and PostgreSQL. Inter body text and Poppins headings are self-hosted as WOFF2 through `next/font/local`, with licenses and provenance under `app/fonts`. Styling uses Tailwind utility classes in components; `app/globals.css` contains only Tailwind import/config directives. The typed Tailwind configuration defines the font families and data-theme selector. Canonical types are generated by the backend's `contracts:types` command and verified by `contracts:check`; browser responses are validated before use.

Follow [AGENTS.md](AGENTS.md) and the installed Next.js documentation before framework changes. Automated checks do not replace manual screen-reader and participant testing. See [readiness](../docs/l1a/readiness.md) for deployment and security boundaries.

See [connected-work behavior](../docs/l1b/implementation.md) and [remaining phase acceptance](../docs/l1b/readiness.md) for the actual local scope.

Connected-work controls include reviewed bulk archive/recovery, project coordination and saved views, calendar preferences/overlays and drag/form review, versioned mail/reply/forward attachments and mailbox actions, connection health, personal/shared collection views, private reviewed templates, authorized mentions and unavailable source previews. All additions use component className utilities and the existing fonts/theme.
